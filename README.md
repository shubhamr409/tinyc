# TinyC — A Small Compiler and Bytecode Virtual Machine

TinyC is a small programming-language project written in **C++17**. It takes a compact, C-like source language, parses it into an abstract syntax tree (AST), generates custom bytecode, optionally optimizes that bytecode, and executes it in a stack-based virtual machine.

The project is intended as a practical exploration of compiler fundamentals—not as a production compiler or a full implementation of the C language.

## Features

- **Lexer:** Recognizes keywords, identifiers, integer literals, operators, delimiters, and `//` comments.
- **Recursive-descent parser:** Parses expressions and supported statements according to operator precedence.
- **Abstract syntax tree:** Represents expressions and statements using C++ classes and `std::unique_ptr` ownership.
- **Bytecode generation:** Converts the AST into a custom stack-based instruction set.
- **Virtual machine:** Executes bytecode using an operand stack and a variable environment.
- **Peephole optimization:** Folds safe constant arithmetic and comparison expressions while keeping jump destinations valid.
- **Control flow:** Supports `while` loops through conditional and unconditional jump instructions.
- **Diagnostics and runtime checks:** Handles invalid input, syntax errors, duplicate or undeclared variables, division by zero, and supported arithmetic overflow cases.
- **Automated tests:** Covers arithmetic, variables, comparisons, loops, optimization, and error handling.

## Supported Language

TinyC currently supports signed 64-bit integer expressions, variables, printing, comparisons, and `while` loops.

| Construct | Example |
|---|---|
| Variable declaration | `let count = 5;` |
| Assignment | `count = count - 1;` |
| Print a value | `print count;` |
| Arithmetic | `2 + 3 * (4 - 1)` |
| Unary negation | `-count` |
| Comparisons | `<`, `<=`, `>`, `>=` |
| Equality | `==`, `!=` |
| Loop | `while (count > 0) { print count; count = count - 1; }` |
| Single-line comment | `// This is a comment` |

Comparison and equality expressions evaluate to `1` when true and `0` when false. Arithmetic expressions are parsed with conventional precedence: multiplication and division before addition and subtraction, with comparisons and equality at lower precedence.

Example program (`examples/while.tc`):

```c
let x = 5;

while (x > 0) {
    print x;
    x = x - 1;
}
```

Output:

```text
5
4
3
2
1
```

Variables must be declared before use, and duplicate declarations are rejected. Variable declarations inside loops are not supported. TinyC does not currently implement functions, `if`/`else`, user-defined types, lexical scopes, or the full C grammar.

## Requirements

- C++17-compatible compiler (GCC, Clang, or MSVC)
- CMake 3.16 or newer
- Ninja build system (for the commands below)

## Build and Test

Run these commands from the project root. Ensure your C++ compiler and Ninja are available on `PATH`.

```powershell
cmake -S . -B build-ninja -G Ninja
cmake --build build-ninja
ctest --test-dir build-ninja --output-on-failure
```

The test executable contains 14 individual checks. A passing CTest run should report `100% tests passed`.

## Command-Line Options

Run a source file:

```powershell
.\build-ninja\tinyc.exe examples\basic.tc
```

Inspect tokens:

```powershell
.\build-ninja\tinyc.exe --tokens examples\basic.tc
```

Inspect the AST:

```powershell
.\build-ninja\tinyc.exe --ast examples\basic.tc
```

Inspect generated bytecode:

```powershell
.\build-ninja\tinyc.exe --bytecode examples\while.tc
```

Inspect optimized bytecode:

```powershell
.\build-ninja\tinyc.exe --optimized-bytecode examples\while.tc
```

Execute optimized bytecode:

```powershell
.\build-ninja\tinyc.exe --optimized examples\while.tc
```

Show instruction-count statistics:

```powershell
.\build-ninja\tinyc.exe --stats benchmarks\optimization.tc
```

## Optimization Example

For the included `benchmarks/optimization.tc` example, the current optimizer reports:

| Metric | Result |
|---|---:|
| Original bytecode instructions | 29 |
| Optimized bytecode instructions | 15 |
| Instructions removed | 14 |
| Instruction-count reduction | 48.28% |

This is a measurement of **static bytecode instruction count for one example**. It does not demonstrate a 48.28% runtime improvement or native-code speedup. Expressions that depend on runtime variable values generally cannot be folded in advance.


## Scope and Limitations

TinyC generates and executes **its own bytecode**. It does not emit native machine code, LLVM IR, NVIDIA PTX, or GPU instructions. Its purpose is to make core compiler stages, bytecode control flow, and a small optimization pass easier to study and demonstrate.
